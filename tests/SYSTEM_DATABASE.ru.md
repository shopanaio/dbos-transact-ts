# Подключение внешней системной базы к тестам SDK

`DBOS_TEST_SYSTEM_DATABASE_FACTORY` указывает путь или имя модуля с экспортом
`systemDatabase` либо `default`: `SystemDatabaseFactory`. Модуль также экспортирует
асинхронную функцию `reset()`, очищающую выделенное тестовое хранилище.
Модуль загружается один раз; поддерживаются CommonJS, ESM и TS через ts-jest.

`tests/helpers.ts` подставляет фабрику и вызывает `reset()` вместо создания
системной базы PostgreSQL. Клиенты используют тот же модуль через
`withTestClientDatabase`. Без переменной окружения сохраняется PostgreSQL-конфигурация.

В datasource-пакетах `withTestSystemDatabase` меняет только системную базу;
база приложения и таблица `transaction_completion` остаются в PostgreSQL.
Общий Jest setup сбрасывает внешнюю системную базу перед каждым тестом.

Сценарии, зависящие от SQL, блокировок PostgreSQL, миграций или SQL API клиента,
помечаются `[postgres-only]`. При внешней фабрике Jest исключает эту метку.
Если SQL используется в общем setup группы, метка ставится на группу.
Такой пропуск не заменяет conformance-сценарий наблюдаемого поведения:
DynamoDB-проект должен учитывать состав пропусков при своей приёмке.

`system-database-factory.fixture.ts` даёт внешнюю фабрику поверх PostgreSQL
для проверки самого механизма подключения. `system-database-port.test.ts`
проверяет изоляцию порта, фабрику, prefetch, отмену и общее состояние процесса.

Проверки в рамках подготовки P0 не запускались по указанию пользователя.
